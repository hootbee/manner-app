# 할 일: 새 문제 쓰기

아래 매너에 새 기본 시나리오 3개를 쓴다.

이 메시지 끝에 다음이 붙는다.

- 매너 id
- 콘텐츠 파일에 이 매너 항목이 있으면 그 항목. 없으면 "매너 항목 없음"
- 이 매너의 기존 시나리오 전부(없으면 빈 배열)

## 쓰는 방법

1. 기존 시나리오와 겹치지 않는 상황을 고른다. 장소, 관계, 시간대, 함께 있는 사람을 바꿔서 같은 원칙이 다른 상황에서도 통한다는 것을 보여 준다. 기획서의 "원칙 하나, 여러 상황"이 이 일의 목적이다.
2. 상황마다 스키마의 형식 설명을 읽고 그 상황에 가장 잘 맞는 형식을 고른다.
3. 형식에 필요한 필드를 스키마대로 모두 채운다. 펼친 문제마다 `area`와 `feedback`이 있어야 한다. 장소를 쓰는 형식이면 장소와 자리 id는 장소별 자리 목록에 있는 것만 쓰고, 정답 자리는 그 문제에 둔 자리 가운데 하나다.
4. 축(`vary`)은 상대나 방향처럼 바꿔도 정답의 이유가 그대로인 경우에만 쓴다. 축은 3개까지다. 축 보기가 지문의 `{변수}` 자리를 채우면 모든 자리가 채워져야 한다.
5. `tags`에는 카테고리 id 목록에서 이 상황에 가장 맞는 것 하나만 넣는다.
6. id는 기존 시나리오의 id 모양을 따른다(원칙 글자로 시작하고 상황을 나타내는 짧은 영어 낱말과 번호를 붙인다). 기존 id와 겹치지 않는다.
7. 매너 항목이 없으면 기획서 콘텐츠 표에서 같은 번호의 줄을 보고 매너 항목(`id`, `name`, `principle`, `places`)을 쓴다. `name`은 그 줄의 매너 문장을 그대로 쓴다. `places`는 이 매너가 일어나는 장소를 한국어 낱말로 쓴다.

## 출력 모양

```
{"manner": <매너 항목 또는 null>, "scenarios": [<기본 시나리오>, <기본 시나리오>, <기본 시나리오>]}
```

- 매너 항목이 이미 있으면 `manner`는 `null`이다.
- 시나리오는 펼치기 전의 기본 시나리오다. 스키마의 시나리오 모양을 따르고 `retired`는 쓰지 않는다.
