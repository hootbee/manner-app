# 할 일: 새 문제 검토하기

이 메시지 끝에 두 가지가 붙는다.

- 원래 문제: 이번에 쓴 펼친 문제 목록(정답과 해설이 있다)
- 블라인드 답: 같은 문제를 정답을 가리고 푼 결과

문제마다 아래 네 가지를 보고, 걸리는 것이 있을 때만 표시를 단다. 표시는 사람이 PR에서 읽고 판단한다. 표시가 실행을 막지는 않으므로, 의심스러우면 다는 편이 낫다. 문제가 없으면 표시하지 않는다.

## 표시 종류

- `정답`: 블라인드 답이 원래 정답과 다르다. 또는 블라인드 답이 같더라도 다른 보기나 다른 자리도 정답이 될 수 있다. `note`에 블라인드 답과, 어느 쪽도 답이 될 수 있는 이유를 쓴다.
- `논란`: 성별 고정관념, 세대 갈등, 상대를 조종하는 기술, 사람마다 의견이 갈리는 주제가 들어 있다. `note`에 문제가 되는 문장과 이유를 쓴다.
- `근거`: 해설(`feedback`, `note`)이나 `evidence`가 근거 요약과 다르다.
- `형식`: 이 상황이 쓴 형식과 맞지 않으면, 스키마의 다른 형식이나 아직 없는 형식 가운데 무엇이 맞을지 한두 문장으로 제안한다.

## 쓰는 방법

- 한 문제에 표시가 여럿이면 종류마다 하나씩 단다.
- 같은 기본 시나리오에서 펼친 문제들이 같은 이유로 걸리면 펼친 문제마다 단다. `id`는 펼친 문제 id다.
- `note`는 한국어 한두 문장이다. 사람이 PR 표의 한 칸에서 읽는다.

## 출력 모양

```
[{"id": "<펼친 문제 id>", "kind": "정답|논란|근거|형식", "note": "…"}]
```

표시가 없으면 빈 배열 `[]`이다.
