## 좌표와 입력

장면은 1536×1024, `AspectRatio(3/2)`와 `BoxFit.contain`으로 배치합니다. 화면 좌표에서 장면의 원점 및 레터박스 여백을 빼고 배율로 나눠 원본 좌표로 변환합니다. 회전축은 **(711, 836)** 입니다. 등받이 레이어 하나만 시계 방향 0–20도로 회전하고 배경·캐릭터·고정 좌석·팔걸이·승객·노트북은 고정됩니다.

민감도는 시작 지점과 현재 지점을 회전축 기준으로 비교한 각도 / 20도이며 0–1로 제한합니다. 이는 게임 조작 범위이며 실제 기차 좌석의 안전 각도나 허용 수치가 아닙니다.

드래그 시작 영역은 `원본 시작 마스크 ∩ 등받이 알파 − 선택 캐릭터/승객/고정 하부/팔걸이/테이블·노트북 알파`입니다. 캐릭터 3종과 초기·고민·동의 상태별 마스크 9개를 따로 계산했습니다. 사각형 히트박스로 대체하지 않습니다. 대화 아이콘 영역 `[150,215,328,390]`을 먼저 확인합니다. 유효하게 시작한 포인터는 그림 밖으로 이동해도 추적하며 손을 놓을 때만 판정합니다.

## 판정과 기록

| 조건 | 판정 | 시도 증가 |
| --- | --- | --- |
| 시작 무효, 취소, 진행률 < 0.10 | 원위치 | 0 |
| 양해 없음, 진행률 ≥ 0.10 | 오답 A | 1 |
| 양해 있음, 0.10–0.45 포함 | 정답 | 1 |
| 양해 있음, 진행률 > 0.45 | 오답 B | 1 |

총 유효 시도는 4회입니다. 조절 중에는 판정하지 않고 O/X는 1.75초, 결과 안내는 계속 표시합니다. 오답 후 다시 시도할 때 양해와 힌트 이력은 유지합니다. 네 번째 오답 뒤 자동 공개하지 않습니다. 직접 정답 확인을 누르면 양해 후 진행률 0.32의 조절 시범을 보여줍니다. 시범은 성공으로 판정하지 않습니다.

기존 01–05 체험용 화면과 동일하게 백엔드 완료/XP 저장을 새로 구현하지 않았습니다. 기존 저장 기록을 수정하지 않고, 정답 공개·복습으로 별도 보상을 지급하지 않습니다. 실제 학습 세션 및 최초 완료 보상은 합의된 `startPractice` 백엔드 연결 작업 범위입니다.

## 에셋 검증과 남은 아트 확인

27개 WebP는 원본 PNG와 RGBA 픽셀이 동일합니다. 9개 마스크가 위 알파 계산과 일치하고, 몽몽이 초기 레이어 합성은 ZIP의 `verification/initial_from_runtime_layers.png`와 픽셀이 같습니다. 원본 ZIP의 manifest에는 SHA256 목록이 없어 별도의 원본 SHA256을 생성했습니다. 잘못된 대화/O/X 경로와 존재하지 않는 mockups 참조를 정리했으며 앱 로딩 시 런타임 경로 누락을 검사합니다.

다음은 기능 버그와 구분되는 **최종 아트 승인 전 확인 사항**입니다.

- 이전 승인 화면에 비해 새 배경의 창문·짐칸·좌석·노트북·뒷승객 위치와 크기가 다릅니다. 이전 승인 원화와 픽셀 일치를 주장하지 않습니다.
- 캐릭터의 초기/고민/긍정 자세와 승객의 5종 표정은 전달된 독립 레이어를 그대로 사용했습니다. 특히 등받이만 기울 때 앉은 캐릭터 몸이 함께 기대지 않는 연출은 제작자 확인이 필요합니다.
- 드래그 마스크는 개발 보정본이므로 디자인 제작자와 최종 합의가 필요합니다.
- 실기기 터치 감도·성능·접점 및 3종 아트 승인은 별도입니다. 사용자 요청에 따라 Android 실기기 검수는 나중에 진행합니다.
- 실제 효과음은 이전 요청대로 보류하고 기존 효과음 주입 지점만 유지합니다.
