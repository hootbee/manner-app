## 구현한 흐름

01번 기본 문제 → 기본 해설의 **응용 문제로 이동** → 캐리어 드래그 응용 문제 → 간단 해설의 **학습 완료** → 독립 완료·리워드 화면 → 실제 02번 기본 문제로 연결했다. 선택 캐릭터를 전 구간에 전달한다. 기존 01~06번의 기본 판정 규칙은 유지했다.

응용 문제는 배경, 선택 캐릭터, 캐리어, 정답 손잡이를 독립 합성한다. 제공된 1536×1024 좌표와 274×410 캐리어를 사용하며, 캐리어에 추가 배율을 적용하지 않는다. 런타임 원본 PNG 25개의 SHA-256을 대조했고, 기존 v8의 관련 PNG·MP3 20개와 판정 좌표도 동일함을 확인했다. 승인 시안 이미지는 화면 전체를 대신하는 용도로 사용하지 않는다.

불투명 픽셀에서 드래그를 시작하고, 이동 중에는 판정하지 않는다. 손을 뗐을 때 전체 점유 영역과 발 영역을 기준으로 통로·다른 승객 침범과 바닥 지지를 검사한다. 무효 드롭·취소에는 시도를 차감하지 않는다. 유효 판정 후에는 승인된 결과 위치로 표시한다. 최대 4회, 힌트 2단계, 최종 정답 공개, 기존 O/X·공통 팝업·효과음 흐름을 재사용했다. 드래그 중 하단 영역 변화로 장면 좌표가 움직이지 않도록 유지했다.

## 해설과 완료 화면

응용 해설은 최종 UI 수정 요청에 따라 기본 해설 컴포넌트를 그대로 재사용한다. 체크 아이콘 핵심 매너 카드, 별 아이콘 학습 핵심 카드, 구분선과 기존 48dp 캐릭터 프로필, 접기·펼치기, 하단 버튼 2개가 동일하다. 승인된 핵심 매너·학습 핵심·실천 문구를 반영했으며 펼치면 짧은 “왜 중요할까요?”와 “실전 팁”만 표시한다. 처음에는 접혀 있고, 다시 풀기는 현재 응용 풀이만 초기화한다. 완료는 기존 리워드 화면으로 이동한다. 작은 화면과 큰 글자는 스크롤로 확인할 수 있다.

독립 완료 화면은 최초 직접 정답, 정답 확인 후 완료, 이미 보상받은 주제 복습의 3가지 상태를 지원한다. 선택 캐릭터 등장·기쁨 동작, 꽃가루, XP 표시, 경험치 게이지를 제공된 애니메이션 단계에 맞춰 한 번 실행한다. 기존 효과음 대기열이 끝난 후 시작하며 완료 화면 자체의 효과음은 추가하지 않았다. 앱이 비활성화되면 애니메이션을 멈추고, 동작 줄이기 설정에서는 최종 상태를 표시한다.

## 보상 연결 범위

사용자 승인 범위는 **체험용 보상 검수와 백엔드 연결 인터페이스 준비**이다. 실제 서버 지급 API나 데이터베이스 변경은 구현하지 않았다.

- 지급량은 `reward_config.json`의 변경 가능한 설정값이다. 현재 최초 직접 완료 20, 정답 확인 후 완료 10, 복습 0 XP이다.
- 기본·응용 해설을 모두 확인한 결과만 완료 요청을 보낼 수 있다.
- 화면은 `TopicCompletionGateway`가 반환하는 지급 결과와 지급 전·후 프로필을 표시한다. 시안의 예시 경험치를 사용하거나 화면에서 레벨을 계산하지 않는다.
- 체험용 구현은 사용자·주제별 최초 지급 기록과 XP를 별도 로컬 저장소에 함께 보관한다. 재진입·동시 요청·저장 후 재시작에서도 중복 지급하지 않고, 저장 실패는 재시도할 수 있다.
- 체험용 레벨은 기존 `FakeBackend`의 정책을 사용한다. 화면 테스트에서는 100이 아닌 레벨 기준값도 검증했다.
- 실제 서비스 연결 시 서버에서 사용자·주제별 유일한 지급을 원자적으로 처리하고, 권위 있는 지급 전·후 프로필을 반환해야 한다. 기기 간 동기화, 실제 로그인 전환 및 서버 트랜잭션 검수는 남아 있다.

`main_prototype.dart`에만 체험용 구현을 주입했다. 실제 앱 진입점에 임의의 로컬 보상 구현을 연결하지 않았다. 기존 `TransportProgress`의 저장 규칙은 변경하지 않았다.
