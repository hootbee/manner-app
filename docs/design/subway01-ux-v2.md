## 드래그 판정 변경

기준 캔버스는 계속 1536×1024이며, 모든 입력은 FittedBox에서 변환된 로컬 좌표를 사용한다.

| 항목 | 이전 | 수정 후 |
|---|---|---|
| 초기 착용 | x821/y610, 160×174 | 동일. 포인터 상대 위치 유지 |
| 시작 터치 | 제공 마스크의 흰 픽셀 | 같은 마스크에 원형 32px 추가 여유. 마스크 바운딩 박스 밖의 넓은 배경은 제외 |
| 이동/드롭 범위 | 가방 중심 (480,495)~(1190,945) | 상황 캔버스 전체. 그림 밖 드롭은 취소·복귀 |
| 정답 | (649,620)~(861,841) | 동일. 백업 JSON과 값이 일치함을 확인 |
| 오답 | (923,752)~(1143,932) | 기존 영역 + 바닥 통로 (96,864)~(1448,980). 좌우 통로 모두 판정 |
| 무효 | 나머지 위치 | 창문·천장·손잡이 등 나머지 위치. 채점·효과음 없이 복귀 |

새 바닥 영역은 정답 영역의 아래(y864 이상)에 있어 서로 겹치지 않는다. 바닥 드롭에서는 실제 놓은 중심에 가방과 X를 표시한다. 기존 원숭이 주변 오답의 가방 배치 및 반응은 유지한다. O/X 타이밍·확대·흔들림·진동·최대 4회·재도전·최종 실패 규칙은 유지했다.

## 선택 캐릭터와 힌트

HomeScreen → LearningCategoryScreen → LearningLessonScreen → TransportLessonScreen → Subway01Screen으로 기존 파트너를 전달한다. 별도 선택 시스템이나 저장소를 만들지 않았다. 홈의 오늘 학습 진입점도 같은 파트너를 넘긴다.

화면 안의 최대 319dp 힌트 줄에서 프로필 56dp + 간격 8dp + 말풍선(최대 255dp)을 사용한다. 좁은 화면에서는 말풍선 너비만 줄인다. 높이는 말풍선 84dp, 외부 96dp, 하단 버튼 슬롯 48dp로 고정한다. 말풍선 좌우 패딩은 16dp이며 배경/꼬리를 먼저 그리고 그 위에 텍스트를 배치한다. 수동 줄바꿈을 넣지 않는다. 큰 글씨는 본문만 스크롤하고 단계 라벨은 고정한다.

힌트 1은 현재 백팩 주변만 은은하게 강조하며 정답 위치·화살표를 노출하지 않는다. 다음 힌트 버튼은 시안처럼 왼쪽의 작은 회색 버튼이다. 힌트 2에서는 추가 버튼만 숨기고 슬롯은 유지한다. 힌트 2의 선택적 정답 가이드는 이번에 추가하지 않았다. 재도전 후 힌트 단계는 기존처럼 유지한다. 힌트를 본 채로도 드래그할 수 있다.

## 헤더·제목·해설

전용 로고 PNG를 새로 만들지 않고, 초기/홈에서 이미 쓰던 `design_reference.webp`의 승인된 로고 영역을 같은 비율로 재사용한다. 로고는 가운데, 뒤로·알림 버튼은 같은 56dp 헤더 양끝에 배치했다. 문제와 해설에서 같은 헤더·진행 캡슐·흑백 버튼을 사용한다.

문제 제목 문구는 유지한다. 단어 안에 보이지 않는 word joiner를 넣어 단어 중간 줄바꿈을 막고, 단어 사이 공백에서는 자동 줄바꿈한다. 접근성 읽기에는 원래 문구를 제공한다. 상황 그림은 자르거나 캐릭터를 옮기지 않고 원래 3:2 비율을 유지한다.

해설의 핵심 매너·왜 중요한가요·학습 핵심 내용은 유지한다. 문제로 돌아가기 보조 버튼과 다음 문제로 이동 주요 버튼을 배치하고 SafeArea/스크롤을 적용했다.

## 효과음과 다음 문제: 남은 자료

**실제 효과음은 아직 재생하지 않는다.** 저장소와 첨부에 정답/오답 음원 및 기존 오디오 재생기가 없다. 요청서에 따라 라이선스 불명 음원을 임의로 넣지 않았다. `LessonFeedbackSound.correct/wrong`와 `LessonSoundPlayer` 주입 구조를 마련했으며, 유효한 판정에서만 한 번 호출한다. `soundMuted`이면 호출하지 않고 재생 실패는 학습 진행을 막지 않는다. 기본 콜백은 null이다. 음원을 제공받으면 앱 진입점에서 해당 플랫폼 재생기를 연결해야 한다.

**실제 다음 응용 문제로의 이동은 아직 연결하지 않았다.** 목록의 2번은 별개의 탑승 질서 문제이며 01번에 연결된 응용 문제와 매핑이 없다. 이를 임의의 다음 문제로 사용하지 않았다. `onNextProblem` 콜백이 실제 연결 정보와 함께 제공될 때 버튼을 활성화하도록 했고, 현재는 비활성 버튼과 준비 안내를 표시한다. 문제로 돌아가기는 기존 결과를 변경하지 않는다. 진행도도 임의로 2/20으로 올리지 않는다.

## 검증

- `flutter analyze --no-pub`: 문제 없음.
- 관련 6개 테스트 파일: 35개 모두 통과. 드래그 상태, 좌우 바닥, 무효/취소, 마스크 여유, 최대 4회, 힌트 단계, 캐릭터 전달, 프로필 3종, 2.5배 글씨, 320/430dp 고정 레이아웃, 정답/오답 사운드 콜백·음소거·오류 처리, 해설 및 다른 기존 문제를 확인했다.
- 경계 검사도 별도로 실행했다. 화면 경계는 통과하지만 기존 `fake/activity_preview.dart → screens/activity_screen.dart`, `fake/wardrobe_preview.dart → screens/wardrobe_catalog.dart` 때문에 `lib/fake` 검사 1건이 실패한다. 해당 파일들은 이번 작업에서 수정하지 않았다. 전체 검사를 통과했다고 기재하지 않는다.
- Android 실기기의 진동·손가락 조작감, 실제 효과음 재생, 실제 응용 문제 이동은 확인하지 못했다. 전체 앱 테스트는 이번 수정에서 다시 실행하지 않았다.

실행 로그 및 초기/힌트1/힌트2/오답/정답/해설 캡처는 저장소 밖 `Documents/Codex/subway01-ux-v2/`에 보관한다. 캡처 글꼴은 `--dart-define`으로 전달했으며 개인 컴퓨터 글꼴 경로를 테스트에 고정하지 않았다.
