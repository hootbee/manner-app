# 02번 응용: 판정 의견과 하차 연출 보완

검수일: 2026-11-26. 이 기록은 v7 최초 구현 보고서의 후속 수정이다. **재승차 정답 영역·스냅 좌표·배율은 사용자 검토 전이므로 변경하지 않았다.**

## 개발자 의견: C안 권장, 범위는 별도 확정

### 1. 현재 정답 영역과 실제 모바일 크기

씬은 1536×1024다. 2단계 정답 발 기준점 영역은 `x=338~568, y=688~902`, 크기는 230×214px이다. 구조물·위험 영역이 우선이며, 이 영역에 발 기준점이 들어오면 `(475,835)`, 배율 `0.58`로 스냅한다. 캐릭터 몸 전체를 작은 정답 사각형에 맞추는 방식은 아니다.

| 화면 너비 | 좌우 여백을 제외한 장면 너비 | 정답 영역의 실제 크기 |
| --- | --- | --- |
| 320dp | 280dp | 약 41.9×39.0dp |
| 360dp | 320dp | 약 47.9×44.6dp |
| 390dp | 350dp | 약 52.4×48.8dp |

원본 QA의 320dp는 장면 표시 너비 기준이다. 실제 앱에서는 화면 양옆 20dp씩을 제외하므로 화면 너비와 장면 너비를 구분해야 한다. 최소 48dp 보완은 **캐릭터를 잡는 터치 영역**이며 정답 드롭 영역을 늘린 것이 아니다.

### 2. 현재 위치의 이유와 한계

현재 위치는 출입문 중앙 통행 구역을 피한 왼쪽 빈 공간이다. 최종 배율로 합성했을 때 세 캐릭터 모두 잔류 승객과 알파 겹침이 없고, 캐릭터가 문턱 밖에 남지 않는다. 이 안전성을 근거로 스냅 위치로 사용할 수 있다.

다만 정확히 `(475,835)`여야만 교육적으로 정답인 이유는 없다. 학습 목표는 먼저 내리는 승객을 배려하고 안전하게 다시 타는 행동이다. 특정 숫자나 눈에 보이지 않는 작은 사각형을 찾게 하는 것은 목표와 맞지 않는다. 현재 발 기준점 영역은 **이동 의도 판정용**이고, 그 안의 모든 점에 몸 전체를 그대로 세워도 안전하다고 검증한 영역이 아니다.

### 3. 단순 확대의 위험

왼쪽은 문틀·차체, 위쪽은 고정 승객, 아래쪽은 문턱, 오른쪽은 문 앞 통행 공간과 가까워진다. 승객 알파와 겹치지 않는 위치도 통행을 막을 수 있다. 따라서 객실 전체를 사각형 하나로 정답 처리하거나, 주변 위치를 확인 없이 모두 안전하다고 인정하면 안 된다.

검수용 후보 계산에서도 `(425,850)`은 세 캐릭터 모두 고정 승객과 겹쳤다. `(525,850)`, `(550,870)`, `(600,850)`은 고정 승객과의 알파 겹침은 0이지만, **통행 공간의 여유와 문 앞 점유 여부는 별도 검토가 필요하다**. 이 후보들을 정답이나 스냅 좌표로 적용하지 않았다.

### 4. A/B/C 중 권장

**C안(안전한 정답 의도 영역 보완 + 이유 설명)**을 권장한다. A안만 적용하면 작은 영역을 찾아야 하는 문제가 남고, B안만 적용하면 왜 다른 곳은 안전하지 않은지 배우기 어렵다. 다만 현재 그림에서 실제로 확보되는 빈 공간을 기준으로 범위를 정해야 하며, C안이 반드시 큰 폭의 확장을 의미하지는 않는다.

권장 해설 방향: “하차 승객을 먼저 보내고, 다시 탑승할 때는 출입문을 막지 않는 안전한 공간으로 이동하는 것이 좋아요.” 범위·스냅 후보와 함께 검토한 뒤 적용한다.

### 5. 권장 판정 방식

- 손가락 자체가 아닌 발 기준점으로 재승차 의도를 판단한다.
- 검수된 복수의 안전 의도 구역을 두고, 통과하면 가까운 안전 스냅 위치를 선택한다.
- 최종 착지 자세는 캐릭터별 몸 전체의 승객·문틀·통행 영역 충돌을 따로 검증한다.
- 명확한 위험 구역은 오답, 구조물·불명확한 배경은 무효로 구분한다. 모호한 공간을 무조건 오답으로 늘리지 않는다.
- 필요하면 힌트 2단계에서 권장 공간을 알려주는 방식도 검토할 수 있다. 이번에는 힌트·해설 원문이나 판정 영역을 바꾸지 않았다.

## 이번에 적용한 수정

### 하차 경로와 속도

1,750ms 전체 시간, 승객 순서, 270ms 출발 간격, 각 670ms 이동, PNG·승강장 대기 위치를 유지했다. 중간 경로의 아래쪽 좌표를 60px 위로 조정하고, 마지막 이동을 오른쪽 화면 밖으로 이어지게 했다. 위치와 배율에는 단조 3차 보간을 사용하며 구간 접점에서 속도가 갑자기 바뀌지 않도록 했다. 출발은 정지 상태에서 가속한다. 경로를 벗어나는 오버슈트는 제한한다.

| 승객 | 기존 마지막 발 좌표 | 새 마지막 발 좌표 |
| --- | --- | --- |
| tote | 1490,1500 | 1650,1250 |
| backpack | 1490,1510 | 1660,1250 |
| office | 1470,1510 | 1670,1250 |
| woman | 1490,1500 | 1680,1250 |
| man | 1500,1530 | 1690,1250 |

캐릭터를 투명하게 지우지 않고 실제 그림이 오른쪽 경계 밖으로 완전히 이동한 뒤 종료한다. **화면 경계를 통과하는 동안 부분 가림은 발생한다.** 하단에서 멈추거나 마지막 순간 강제로 사라지는 처리는 아니다. PNG의 대기·보행 자세 차이는 승인된 에셋을 그대로 유지했다.

`passenger_animation.json`의 실제 경로와 `asset_rules.json`, `state_asset_mapping.json`의 중복 종료 좌표를 동기화했다. 원본 PNG 22개와 `drag_zones.json`은 v7 해시와 일치한다. `source_sha256.json`은 v7 원본 기준이고, **현재 수정본 26개 파일**의 크기·해시는 `integration_manifest.json`으로 검증한다.

### 상태별 안내

- 1단계: “캐릭터를 드래그해 보세요. · 1/2단계”
- 하차 중: “승객들이 내리는 중이에요.”
- 2단계 준비: “하차가 끝났어요! 안전하게 다시 탑승해 보세요. · 2/2단계”

안내 영역의 높이를 긴 문구 기준으로 확보해 전환 시 그림 위치가 흔들리지 않도록 했다. 하차 중에는 입력을 받지 않고, 다섯 경로 완료와 안전 조건 충족 후에만 2단계를 연다.

## 재승차 로직 확인과 영상 수정

이전 `application02-exiting.mp4`는 하차 프레임 다음에 최종 성공 장면을 붙인 검수 자료여서, 두 번째 드래그 과정이 생략돼 보였다. 이번에는 실제 포인터 입력으로 전체 과정을 기록했다.

하차 후 아무 입력 없이 10초를 진행시켜도 준비 상태를 유지하고 성공하지 않는 것을 검사했다. 유효 정답 드롭 후에만 210ms 스냅, 최종 O, 공통 팝업, 해설로 진행한다. 오답은 X와 횟수 증가, 무효는 무차감이며 두 단계 합산 유효 오답 4회 제한은 유지한다. 정답 공개는 직접 성공이 아니다.

**02번 XP 지급 자체는 아직 연결 전이다.** 이번에도 임의의 보상량이나 지급 처리는 추가하지 않았다. 1단계·정답 공개 시 지급은 없고, 최종 성공 뒤 해설 연결을 유지한다. 01번의 보상 설정을 복사하지 않는다. 실제 보상 연동 시에는 02번 완료 정책·지급량을 별도로 확정해야 한다.

새 영상: `C:/Users/gjo49/Documents/Codex/application02-revision-review/application02-full-interaction.mp4`.

원본 실행 기록은 176프레임/20fps(8.8초)이며 영상 끝에 1초 정지 화면을 덧붙인다. 1단계 드래그 17프레임, 하차 35프레임(1,750ms), 2단계 준비 11프레임, **사용자의 재승차 드래그 17프레임**, 최종 스냅·피드백·팝업·해설이 모두 포함된다. 파란 터치 표시는 검수 영상에만 덧그린 것이며 앱 UI는 아니다. 실제 휴대폰 녹화가 아닌 Flutter 위젯 실행 프레임으로 구성한 자료다.
