# 0004. 학습 엔진: Leitner 복습, 영역 스탯, 데일리 위치와 출제 순서

상태: 채택
날짜: 2026-10-25

## 배경
화면은 `Home.reviewsDue`, `AreaStat.value`(0~100), `DayCard`, `Finished.retryTomorrow`를 받는다(ADR 0002 §2). 이 값을 내는 규칙이 아직 없다. ADR 0001 §4는 Leitner 확정을, ADR 0003 결과 절은 콘텐츠에 없는 `scenario_id`·`day_id` 처리 확정을 이 ADR로 미뤘다. ADR 0002 작업 8(`engine/`)을 시작하려면 지금 정해야 한다.

XP, 레벨, 연속 학습일은 `docs/decisions.md`와 ADR 0001 §4에 정해져 있고 `feat/engine-basics`에서 구현 중이다. 여기서는 다시 정하지 않는다.

원칙은 두 가지다.
- 모든 값은 **기록 집합 + 콘텐츠 + 오늘 날짜**로 계산하고, 아무것도 저장하지 않는다. 같은 날 안의 기록 순서에 기대지 않는다(ADR 0001 §4).
- **언제나 단순한 시스템**(2026-10-25 사용자): 규칙마다 한 문장으로 설명되게 하고, 예외 규칙과 조정 손잡이를 두지 않는다.

## 결정
### 1. 날짜와 기록 타입
- 엔진은 어떤 `DateTime`을 받든 연월일만 쓴다. 시각과 시간대는 무시한다(`feat/engine-basics`의 `engine.dart`와 같다).
- 오늘 날짜는 `live/`가 기기 시계로 만들어 넘긴다. 엔진은 `DateTime.now()`를 부르지 않는다. 그래야 테스트가 날짜를 고정할 수 있다.
- 기록 타입(`Attempt`, `DayCompletion`, `Grade`)은 `engine/engine.dart`의 것을 쓴다. `backend.dart`에도 `Grade`가 있으므로 `live/`에서는 `import ... as engine;`처럼 접두를 붙여 구분한다.

### 2. Leitner (매너 단위)
- 칸은 1·2·3이고, 간격은 1·3·7일이다. 모든 매너는 1칸에서 시작한다.
- (매너, 날짜)마다 그날 그 매너의 기록이 모두 `best`면 한 칸 오르고(최대 3칸), 하나라도 아니면 1칸으로 간다. 데일리, 다시 풀기, 카테고리 연습 기록이 모두 들어간다.
- 다음 복습일은 그날 + 새 칸의 간격이다. 처음 푼 날 맞히면 2칸이 되고 3일 뒤가 복습일이다. 3칸에서 또 맞히면 3칸에 머물고 7일 뒤에 다시 온다.
- **복습 대상**은 은퇴하지 않은 매너 중 복습일이 오늘이거나 지난 것이다. `reviewsDue`는 그 수다. 한 번도 안 푼 매너는 복습 대상이 아니다.
- **밀림**은 복습일이 오늘보다 앞선 상태다(복습일 당일은 밀린 것이 아니다).

```dart
// engine/leitner.dart
const intervals = {1: 1, 2: 3, 3: 7}; // 칸 → 다음 복습까지 일수

class Box {
  const Box(this.n, this.due);
  final int n;         // 칸 1~3
  final DateTime due;  // 다음 복습일
}

/// 매너 id → 칸. 매너를 찾지 못한 기록은 뺀다(5절).
Map<int, Box> boxes(Content c, Iterable<Attempt> attempts);

/// 복습 대상(은퇴하지 않았고 due <= today)인 매너 수.
int reviewsDue(Content c, Map<int, Box> boxes, DateTime today);
```

### 3. 영역 스탯 (0~100, 6개 고정 순서)
- 영역 순서는 `연애, 친구, 어른·가족, 직장, 공공장소, 메시지`다(ADR 0003 §3). `engine/areas.dart`에 상수 `areas`로 둔다.
- 영역 스탯 = `min(100, 그 영역에서 푼 매너들의 칸 수 합 × 5)`.
- "그 영역에서 푼 매너"는 사용자가 그 영역 문제(펼친 문제의 `area`)로 기록을 남긴 매너다. 매너 1을 연애 문제로만 풀었다면 연애에만 들어간다.
- 밀린 매너는 한 칸 낮게 친다(1칸이 밀리면 0).
- 은퇴한 매너는 영역 스탯에서 뺀다.

```dart
// engine/areas.dart
const areas = ['연애', '친구', '어른·가족', '직장', '공공장소', '메시지'];

/// areas 순서 그대로 6개. live/는 AreaStat(area, value)로 옮기기만 한다.
List<(String area, int value)> areaStats(Content c, Iterable<Attempt> attempts,
    Map<int, Box> boxes, DateTime today);
```

예: 매너 1을 연애 문제로 10-25에 맞히면 2칸이 되고 연애 영역 스탯은 10이다. 10-29가 되면 밀려서 5가 된다. 3칸 매너가 7개면 105가 되지만 상한 때문에 100이다.

### 4. 데일리 진행 위치와 세트 순서
**위치** (`dailyPosition`)
- 경로는 은퇴하지 않은 `days`를 배열 순서대로 늘어놓은 것이다.
- `next`는 경로에서 완료 기록이 없는 첫 하루다.
- `doneToday`는 오늘 날짜의 완료 기록이 하나라도 있으면 참이다. 모르는 `day_id`도 센다.
- 보여 줄 하루는 오늘 마친 하루(콘텐츠에 있는 것 중 배열에서 마지막)이고, 그런 하루가 없으면 `next`다. 둘 다 없으면 `null`이다(`Home.today == null`).
- `number`는 경로에서 몇 번째인지(1부터)이고, `nextTitle`은 `doneToday`일 때만 `next`의 제목이다.

**세트 구성** (`planDay`)
- 장면 3개이고 장면마다 문제 2개다(엔진 상수 `perScene = 2`). 순서는 장면 순서대로이고, 장면 안에서는 장면 매너 문제가 먼저다.
- 복습 섞기: 복습 대상 매너 중 오늘 장면 매너가 아닌 것을 복습일이 오래된 순(같으면 매너 id 순)으로 최대 3개 골라, 장면 1·2·3의 둘째 문제 자리에 넣는다. 복습 대상이 없는 장면은 장면 매너 2문제다.
- 문제 고르기: 그 매너의 출제 가능한 문제 중 마지막으로 푼 날이 가장 오래된 것부터 고른다. 안 푼 문제가 가장 오래된 것이고, 같으면 무작위다. 이 세트에서 이미 고른 문제는 다시 고르지 않는다.
- 무작위는 `Random`을 인자로 받는다. 테스트는 `Random(seed)`를 넣고, 기대값으로는 성질만 확인한다.

**다시 풀기** (세트 진행, `live/`의 `Session`)
- `best`가 아닌 문제는 같은 문제를 세트 맨 뒤에 `retry: true`로 다시 넣는다. 다시 풀기도 같은 규칙을 따르므로 맞힐 때까지 반복된다.
- 진행 상태(지금 몇 번째 문제인지, 남은 큐)는 `Session` 구현이 들고 있다. 위 규칙 한 줄이 전부라서 엔진 함수를 두지 않는다.
- `retryTomorrow`는 이 세트 기록 중 `best`가 아닌 것이 있는 매너 이름이다(처음 나온 순서). 2절에 따라 이 매너들은 내일이 복습일인 1칸이 된다.

```dart
// engine/daily.dart
const perScene = 2;

/// 오늘 홈에 보여 줄 하루. null이면 준비된 하루가 없다.
({Json day, int number, bool doneToday, Json? next})? dailyPosition(
    Content c, Iterable<DayCompletion> done, DateTime today);

/// 장면마다 문제 id 2개(3장면).
List<List<String>> planDay(Content c, Json day, Iterable<Attempt> attempts,
    Map<int, Box> boxes, DateTime today, Random rng);

/// 이 세트에서 best가 아닌 기록이 있는 매너 이름.
List<String> retryTomorrow(Content c, Iterable<Attempt> session);
```

### 5. 콘텐츠에 없는 id (ADR 0003 결과 절 확정)
기록은 지우거나 고치지 않는다. 계산할 때만 아래처럼 다루고, 콘텐츠를 받으면 다시 계산해서 반영된다. 매너와 문제는 `Content.lookup`으로 찾는다.

| 기록 | 찾은 것 | XP | Leitner·복습 대상 | 영역 스탯 | 연속 학습일 | 데일리 위치 |
| --- | --- | --- | --- | --- | --- | --- |
| 펼친 문제가 있음(은퇴 포함) | 매너, 문제 | 넣음 | 넣음 | 넣음 | — | — |
| 펼친 문제는 없고 기본 시나리오는 있음 | 매너만 | 넣음 | 넣음 | 뺌(문제의 영역을 모름) | — | — |
| 둘 다 없음 | 없음 | 넣음 | 뺌 | 뺌 | — | — |
| `day_id`가 콘텐츠에 있음 | — | — | — | — | 넣음 | 넣음 |
| `day_id`가 콘텐츠에 없음 | — | — | — | — | 넣음 | 뺌(`doneToday`에는 넣음) |

은퇴한 매너는 Leitner 계산은 하되 복습 대상과 영역 스탯에서는 뺀다(2절·3절).

## 고려한 대안
- **다시 풀기를 같은 매너의 다른 상황으로**(바꾸기 전 `docs/decisions.md`): 다른 기본 시나리오를 고르는 함수와 예외 순서가 필요하고, 매너마다 문제 3개를 보장해야 한다. 2026-10-25 사용자 결정으로 같은 문제 다시 풀기로 바꿨다.
- **기한 전에 맞히면 칸 유지**: 같은 매너를 연달아 풀어 칸이 빨리 오르는 것은 막지만, 규칙에 예외가 하나 생긴다. 맞히면 언제든 오르도록 했다.
- **영역 스탯을 영역 매너의 평균 칸으로**: 100이 "다 익힘"을 뜻하지만, 콘텐츠에 매너가 늘면 사용자의 값이 내려간다. 견본처럼 맞힌 수 × 5로 하면 복습이 밀려도 내려가지 않아서 기획서("복습이 밀리면 내려간다")와 어긋난다.
- **칸 상태를 로컬에 저장**: 기기 두 대, 늦게 도착한 기록, 콘텐츠 변경이 있을 때마다 다시 맞춰야 한다. 기록이 수만 개여도 한 번 훑는 계산이라 저장할 이유가 없다.

## 결과
- **쉬워지는 것**: 홈과 스테이터스 값은 `boxes`, `reviewsDue`, `areaStats`, `dailyPosition` 네 함수의 결과다. 기록이나 콘텐츠가 바뀌면 다시 부르기만 하면 된다. 테스트는 기록 목록과 날짜만 만들면 된다.
- **어려워지는 것**: 홈을 그릴 때마다 전체 기록을 훑는다. 은퇴한 매너는 스테이터스에서 사라진다.
- **확인할 점**
  - 네트워크 없음: 모든 계산이 로컬 기록과 번들 콘텐츠로 된다.
  - 같은 요청 두 번: Leitner는 "그날 모두 best인가"만 보므로 같은 기록이 두 번 있어도 결과가 같다. XP는 로컬 DB의 id 기본 키가 중복을 막는다(ADR 0001 §3).
  - 기기 두 대: 같은 날 한 기기는 맞히고 다른 기기는 틀리면, pull 뒤 두 기기 모두 1칸으로 판정한다. 콘텐츠 버전이 다르면 잠시 값이 다를 수 있고, 콘텐츠를 받으면 같아진다. 기기 시계가 앞서 `solved_on`이 오늘보다 늦은 기록은 복습일이 늦어질 뿐이다.
  - 콘텐츠 업데이트: 시나리오의 `manner`를 바꾸는 것은 CI가 막는다(ADR 0003 §6). 문제의 `area`를 바꾸면 영역 스탯이 바뀌는데, 이는 의도한 동작이다.
  - 탈퇴: 기록이 지워지면 모든 값이 0과 `day-01`로 돌아간다. 따로 할 일은 없다.
- **알고 받아들인 한계**
  - 같은 매너가 이틀 연속 나와서 맞히면 이틀 만에 3칸이 된다.
  - 다시 풀기는 정답을 본 뒤 같은 문제를 푸는 것이라 맞히기 쉽고, XP도 그만큼 받는다(XP는 모든 풀이의 합, `docs/decisions.md`). 그날 이미 틀렸으므로 Leitner에는 영향이 없다.
  - 한 장면의 두 문제가 같은 기본 시나리오의 변형일 수 있다(`A-sidewalk~partner.right`와 `~partner.left` 등). 사용자 테스트에서 지루하다는 말이 나오면 그때 기본 시나리오가 다른 것부터 고르게 한다.
  - 매너 30개가 모두 3칸이면 하루 평균 약 4.3개가 복습일이 되는데, 복습 칸은 하루 3개다. 밀린 것은 복습 대상에 남고, 오래된 것부터 나온다.
- **넣지 않은 것과 넣을 시점**
  - 계산 결과 캐시: 실제 기기에서 홈 계산이 한 프레임(16ms)을 넘는 것이 측정되면 넣는다.
  - 채점 함수(`Answer` → `Grade`): ADR 0002 작업 7(콘텐츠 → `Question`)과 같은 작업에서 정한다.
  - 카테고리 연습 출제: 카테고리 기준이 정해지면 `planDay`의 문제 고르기 규칙을 그대로 쓴다.
- **다시 볼 조건**: 간격(1·3·7일)을 바꿀 때(`docs/decisions.md`가 먼저 바뀐다), 영역 스탯이 너무 빨리 100이 된다는 의견이 나올 때.

## 다른 문서에 미치는 영향
채택하면서(2026-10-27) 문서는 함께 고쳤다. 3번의 검사기 코드(`validate.dart`의 3개 → 2개)는 따로 고친다.

1. `docs/decisions.md` 학습 규칙의 "세트 안 재도전은 같은 매너의 다른 상황으로": 이번에 "틀린 같은 문제를 세트 맨 뒤에, 맞힐 때까지"로 고쳤다(2026-10-25 사용자 승인).
2. ADR 0003 §2 "스테이터스의 영역 값은 은퇴한 항목으로도 찾는다": 이 ADR은 은퇴한 매너를 영역 스탯에서 뺀다. 결과 절의 "영역 값"이라는 용어도 "영역 스탯"으로 바꿔야 한다.
3. ADR 0003 §6 검사표
   - "출제 가능한 펼친 문제 3개 미만 오류(장면 2문제와 다시 풀기 1문제)": 이제 다시 풀기는 같은 문제를 쓰므로 장면 2문제를 채울 2개면 된다.
   - "출제 가능한 기본 시나리오 3개 미만 경고(다시 풀기·복습은 다른 상황으로)": 근거가 사라진다.
   - 이 두 검사는 `app/lib/content/validate.dart` 101~102행과 `app/test/validate_test.dart` 232~248행에 구현되어 있다.
4. `docs/concept.md` 학습 방식 3·4번
   - "다시 풀기와 복습 모두 같은 문제가 아니라 같은 매너의 다른 상황 문제를 낸다. 그래서 매너마다 상황 문제가 3개 이상 필요하다": 다시 풀기는 같은 문제로 바뀌었다. 복습은 "가장 오래전에 푼 문제부터"라서 대개 다른 문제가 나오지만, 다른 기본 시나리오라는 보장은 없다.
   - 3번의 "세트 끝에 한 번 더"는 "맞힐 때까지"로 바뀐다.
5. ADR 0002
   - §3 `FakeBackend`의 "오답이면 같은 세트에 `retry: true` 문제를 한 번 더 내고": 같은 문제를 세트 맨 뒤에, 맞힐 때까지 내도록 바뀐다. 작업 1의 테스트("한 번 더 온다")는 그대로 맞고, "다시 틀리면 또 온다"를 더한다.
   - §2 `Answered.nextScene`·`last`, `Phase.progress`: 다시 풀기가 마지막 장면 뒤에 붙으므로 다시 풀기 문제의 `nextScene`은 null이다. `last`는 큐가 비었을 때만 참이다. 진행 바는 큐가 늘면 뒤로 갈 수 있다. 화면 경계는 그대로이고, 주석만 맞추면 된다.
6. ADR 0001 §4의 Leitner 예시("모두 best면 승급, 아니면 1단계"): 이 ADR과 같다. 바꿀 것 없음.

## 열린 질문 (사용자 결정 필요)
없음.

정해진 것(2026-10-25 사용자)
- 원칙은 "언제나 단순한 시스템"이다.
- Leitner: 1칸에서 시작한다. 그날 모두 `best`면 한 칸 오르고(기한 전이어도), 아니면 1칸이다. 3칸이면 7일마다 다시 온다.
- 영역 스탯: `min(100, 그 영역에서 푼 매너의 칸 수 합 × 5)`이고, 밀린 매너는 한 칸 낮게 친다.
- 복습 섞기: 복습 대상 매너를 오래된 순으로 최대 3개, 장면의 둘째 문제 자리에 넣는다.
- 다시 풀기: 틀린 같은 문제를 세트 맨 뒤에, 맞힐 때까지 낸다(`docs/decisions.md` 수정).
- 은퇴한 매너는 영역 스탯에서 뺀다.
