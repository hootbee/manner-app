# 매너 트레이닝 앱 컨셉 기획서

Oct 12, 2026 · @hootbee

## 컨셉 요약

매너와 센스를 하루 5분 반복 훈련으로 몸에 익히게 하는 앱이다. 한마디로 "매너판 듀오링고"다.

- 대상 영역: 연애, 친구, 어른·가족, 직장, 공공장소, 메시지
- 핵심 방식: 원칙 하나를 여러 상황 문제로 반복하고, 틀린 원칙은 간격을 두고 다시 낸다.
- 대표 문제 형식: 위에서 내려다본 그림에서 내가 설 자리를 탭하는 퀴즈
- 앱 실행 중에는 AI를 쓰지 않는다. AI는 문제를 만들고 검토하는 제작 단계에서만 쓴다.

## 배경과 문제

매너는 알고 있어도 실제 상황에서 바로 나오지 않는다. 아는 것과 몸에 밴 것 사이의 차이가 이 앱이 푸는 문제다.

- 검색과 ChatGPT는 물어볼 때 답을 주지만, 그 상황을 미리 알고 묻는 사람은 드물다.
- 한 번 읽은 매너는 잇혀진다. 실전에서는 생각할 시간 없이 반응해야 한다.
- 상황별 정답만 외우면 처음 보는 상황에 응용하지 못한다.

그래서 이 앱은 정보를 제공하지 않고 판단을 훈련시킨다. 원칙을 여러 상황에서 반복해 처음 보는 상황에서도 원칙이 저절로 떠오르게 하는 것이 목표다.

## 타깃 사용자와 영역

주 대상은 사회생활과 연애에서 "눈치 있는 사람"이 되고 싶은 20\~30대다. 취준생, 사회초년생, 연애를 시작하는 사람이 여기에 속한다.

| 영역 | 다루는 장면 |
| --- | --- |
| 연애 | 데이트, 동행, 식사, 헤어진 뒤 연락 |
| 친구 | 약속, 방문, 선물, 사진 |
| 어른·가족 | 식사 자리, 술자리, 동행 |
| 직장 | 상석, 차량, 엘리베이터, 명함, 감사 인사 |
| 공공장소 | 대중교통, 출입문, 우산 |
| 메시지 | 연락 시간, 답장 속도, 지각 연락 |

연애와 일상 영역에 무게를 두고, 직장·의전은 보조 영역으로 둔다. 대화 연습(소개팅 대화, 고백 등)은 다루지 않는다.

## 핵심 설계: 원칙 하나, 여러 상황

콘텐츠는 상황별 정답이 아니라 원칙 8개를 기준으로 묶는다. 한 원칙을 여러 영역의 문제로 반복해야 처음 보는 상황에도 응용할 수 있다.

&#91;embedded content: 원칙 A · 다섯 상황으로 반복\]

복습 때는 같은 문제 대신 이 다섯 상황 중 다른 하나를 낸다.

| 원칙 | 대표 매너 |
| --- | --- |
| A. 안전하고 편한 쪽을 상대에게 | 동행자를 인도 안쪽으로, 우산은 상대 쪽으로 |
| B. 상대 먼저 | 내리는 사람 먼저, 어른이 수저를 든 뒤 식사 |
| C. 미리 챙기기 | 수저와 물 먼저 챙기기, 약속 장소 먼저 도착 |
| D. 상대 속도에 맞추기 | 걸음 속도, 답장 길이, 식사 속도 맞추기 |
| E. 공간과 소리 배려 | 백팩 앞으로, 통로 막지 않기 |
| F. 연락 시간 배려 | 늦은 밤 연락 자제, 지각 시 미리 연락 |
| G. 반응과 감사 표현 | 선물은 받은 자리에서 반응, 다음 날 감사 메시지 |
| H. 소개와 인사 | 명함은 두 손으로, 글씨가 상대 쪽을 향하게 |

학습 경로는 원칙이 아니라 "하루 일과"로 짠다. 하루(장)마다 중심 원칙을 1\~2개로 정하고, 그날의 장면(출근길, 점심, 퇴근 등)이 노드가 된다. 원칙은 장면에 태그로 붙고, 복습과 스킬 레벨은 원칙·매너 단위로 계산한다. 듀오링고식 원형 노드 경로와 달리, 홈 화면에서부터 "상황 훈련" 앱임이 보이게 하려는 선택이다.

## 학습 방식과 문제 형식

홈은 하루 일과 경로다. 장면 노드 하나가 레슨 하나(2문제)이고, 새 문제와 복습 문제를 섞어서 낸다. 하루는 약 6문제, 3분이다(2026-10-25). 그날 장면을 섞은 "하루 돌아보기"(시간 제한)는 MVP 이후다.

학습은 두 갈래다. 둘 다 미리 만들어 둔 같은 문제 풀에서 문제를 꺼낸다.

- 데일리: 하루 일과 경로. 매일 장면 3개, 약 3분이다. 연속 학습일이 여기에 붙는다. 주간 보상은 MVP에서 뺐다(2026-10-25).
- 카테고리별 연습: 카테고리 하나를 골라 원하는 만큼 푼다. XP는 받지만 연속 학습일에는 들어가지 않는다. 카테고리 기준은 추후 결정한다.

문제마다 카테고리 태그를 붙인다. 데일리는 그날 장면에 맞는 문제를 고르고, 카테고리 연습은 해당 카테고리 문제를 묶어서 낸다. 두 곳의 풀이 기록은 같은 복습 일정에 쌓인다.

1. 오늘의 세트를 푼다.
2. 답하면 바로 리액션을 보여준다. 해설은 정답 한 줄, 이유 한 줄, 원칙 문구(예: 원칙 A "위험은 내가, 편한 건 상대가")만 쓴다. 출처는 "근거 보기"에 접어 둔다.
3. 틀린 매너는 세트 끝에 한 번 더 낸다(다시 풀기). 그리고 매너 단위로 Leitner 복습 일정에 넣어 1일, 3일, 7일 뒤에 다시 낸다.
4. 다시 풀기와 복습 모두 같은 문제가 아니라 같은 매너의 다른 상황 문제를 낸다. 그래서 매너마다 상황 문제가 3개 이상 필요하다.
5. 익숙해진 원칙은 시간 제한 모드(3\~5초)로 낸다. 생각하기 전에 반응하도록 훈련하는 단계다. MVP 이후(2026-10-25).

| 형식 | 방식 | 잘 맞는 매너 |
| --- | --- | --- |
| 위치 | 위에서 내려다본 그림에서 자리를 탭한다 | 인도 안쪽, 상석, 택시 자리 |
| 순서 | 행동 카드를 순서대로 놓는다 | 명함 교환, 승하차, 식사 시작 |
| 상황 선택 | 상황을 읽고 가장 무난한 행동을 고른다 | 선물 반응, 지각 연락 |
| OX | 행동이 매너에 맞는지 판단한다 | 걸음 속도, 백팩 |

게임 요소는 RPG의 수치 체계만 가져오고, 세계관과 꾸미기 상점은 넣지 않는다. 목표는 "문제를 푸는 게 아니라 게임을 하고 있다"는 느낌이다.

- 리액션: 답한 직후 장면이 움직인다. 예를 들어 차가 물을 튀기면 차도 쪽에 선 사람이 맞는다. 효과음, 진동, 연속 정답 콤보를 함께 쓴다.
- 스테이터스 창: 영역 6개(연애, 친구, 어른·가족, 직장, 공공장소, 메시지)를 육각형 스탯으로 보여준다. 스탯은 그 영역 매너들의 복습 단계로 계산하고, 복습이 밀리면 내려간다.
- 스킬: 원칙 A\~H를 스킬로 보여준다(예: "위험은 내가 Lv.3"). MVP 이후.
- 칭호: 높은 스탯과 스킬 조합으로 정한다(예: 든든한 동행러). 스탯과 칭호는 공유 카드로 저장할 수 있다. MVP 이후.
- 연속 학습일, XP, 배지는 유지한다. 하트(목숨)와 랭킹은 넣지 않는다.
- 스탯 이름은 사람을 평가하는 말을 피한다. "연애 Lv.1" 대신 "연애 센스 12"처럼 쌓여 가는 숫자로 보여준다.
- 옷차림: 하루를 마칠 때마다 의상 아이템(넥타이핀, 커프스, 행커치프 등)을 하나 얻고, 스테이터스 창의 수트 실루엣에 입힌다. 아이템은 하루 완료로만 얻는다. MVP 이후(2026-10-25 결정). 주기(매일/매주)는 넣을 때 정한다.
- 연속 학습일 아이콘은 불꽃 대신 넥타이를 쓴다. 원형 노드 대신 장면 카드를 써서 듀오링고와 겉모습을 다르게 한다.

## 콘텐츠

초기 문제 풀은 최대한 많이 만든다. 데일리와 카테고리 연습이 같은 풀을 쓰기 때문이다. 매너 30개에서 시작하고, 변수 조합과 생성 파이프라인으로 매너당 문제를 늘린다.

콘텐츠 원칙:

- 성별 중립 표현을 쓴다. "여성은 차도 반대쪽" 대신 "동행자를 인도 안쪽으로"라고 쓴다.
- 데이트 비용처럼 의견이 갈리는 주제는 다루지 않는다.
- 조종 기술("꾸시는 법", "밀당")처럼 보이는 내용은 넣지 않는다. 기준은 존중, 배려, 상대의 편안함이다.
- 채점은 "가장 무난한 선택", "괜찮은 선택", "피해야 할 선택" 3단계로 한다. 상황 선택 보기는 정답이 가장 길지 않도록 길이를 맞춘다.
- 상석·의전 항목(4, 5, 6, 30번)은 공신력 있는 근거를 확인한 뒤에 문제로 만든다.

## AI 활용 방식

앱 실행 중에는 AI를 쓰지 않는다. 출제, 채점, 복습 일정은 정적 콘텐츠와 알고리즘으로 처리해서 API 비용과 장애 위험이 없다.

AI는 문제를 만드는 제작 단계에서만 쓴다. 생성과 검토를 에이전트로 묶고, 사람은 표시된 문제만 판단해 승인한다. 생성·검토 모델은 Claude를 쓴다.

1. 기획 에이전트가 매너별로 기존 문제와 겹치지 않는 새 상황 후보를 고른다.
2. 생성 에이전트가 문제 JSON(지문, 보기, 피드백, 그림 자리)을 쓴다.
3. 코드로 검사한다. JSON 형식, 템플릿·자리 id, 정답 보기 길이, 매너당 3문제 이상, 금지 표현을 확인한다.
4. 검토 에이전트가 세 가지를 본다.
   - 블라인드 풀이: 정답을 모르는 상태로 여러 번 푼다. 답이 갈리면 "정답 애매", 모두 쉽게 맞히면 "너무 쉬움"으로 표시한다.
   - 논란 검사: 성별 고정관념, 세대 갈등, 조종 기술처럼 보이는 내용을 찾는다.
   - 근거 검사: 관례형·의전 문제를 출처 문서와 대조한다. 의전 문서는 Postgres `pgvector`에 넣어 검색한다.
5. 사람이 표시된 문제와 무작위 일부를 GitHub PR에서 확인하고 승인한다.
6. 출시 후에는 오류 신고와 문제별 정답률(예: 95% 오답, 100% 정답)로 다시 검토할 문제를 고른다.

- 생성과 검토를 같은 계열 모델이 하면 맹점도 같다. 그래서 사람 승인 단계는 없애지 않는다.
- 파이프라인은 서버 기능이 아니라 별도 스크립트다. 콘텐츠 팩 주기에 맞춰 GitHub Actions로 돌리고 결과를 PR로 올린다. 승인하면 Supabase Storage에 올라간다.
- 해설 화면의 "근거 보기"는 저장된 출처만 보여준다. 앱 실행 중 LLM이 필요 없다.
- 라이선스: 공공기관 문서는 공공누리 유형을 확인한다. 스토어 출시를 생각하면 출처 표시 후 상업적 이용과 변경이 모두 가능한 1유형만 쓴다. 책과 블로그 글은 근거 자료로 넣지 않는다.

## 경쟁 앱과 차별점

한국어로 성인의 생활 전반 매너를 반복 훈련하는 앱은 조사에서 찾지 못했다. 다만 검색 도구가 미국 기준이라 한국 앱스토어는 직접 다시 확인해야 한다.

| 앱 | 대상 | 방식 | 우리와 다른 점 |
| --- | --- | --- | --- |

| [Sabrina](https://studio.com/apps/sabrina) | 성인 | 주 단위 레슨 + 실전 과제 | 영어 기반, 반복 훈련 구조가 아니다 |

우리 차별점:

- 한국어, 성인, 생활 전반(연애·일상·어른·직장)을 한 앱에서 다룬다.
- 원칙 하나를 여러 상황에 반복하고, 간격 반복으로 다시 낸다.
- 위치를 탭하는 그림 퀴즈로 몸으로 기억하게 한다.
- AI 없이 동작해 비용이 들지 않고, 정답이 명확하며, 근거를 인용할 수 있다.

대화 연습은 AI 연애 앱들이 더 강하므로 핵심 영역에서 뺀다.

## MVP 범위와 기술 구성

> 기술 결정의 원본은 [`docs/decisions.md`](decisions.md)다. 이 절과 다르면 그쪽을 따른다.

MVP는 매너 30개, 넉넉한 초기 문제 풀, 문제 형식 4종, 간격 반복, 연속 학습일, 계정 연동이다. 새 리포지토리에서 처음부터 만들고 기존 ReQuest 코드는 가져오지 않는다. 앱 성격이 달라 재사용 이점이 작다.

화면:

1. 온보딩, 게스트로 바로 시작, 로그인(Google, 사용자가 백업을 원할 때)
2. 홈: 하루 일과 경로, 연속 학습일, 오늘의 복습 수
3. 카테고리별 연습: 카테고리 선택, 카테고리별 연습 세트
4. 문제 풀이: 위치, 순서, 상황 선택, OX
5. 해설: 이유, 원칙, 근거 보기
6. 스테이터스 창: MVP는 영역 스탯(0~100 육각형)만 만든다. 원칙 스킬, 칭호, 옷장, 약한 매너는 MVP 이후이며, 팀원의 UI 개발 속도를 보고 다시 정한다(2026-10-25).
7. 설정: 알림, 회원 탈퇴, 개인정보처리방침

| 구성 | 선택 | 이유 |
| --- | --- | --- |
| 앱 | Flutter | 지금은 Android만 출시한다. 나중에 iOS를 같은 코드로 낸다 |
| 인증 | Supabase Auth: Google 로그인 | 로그인 수단을 하나로 줄인다 |
| DB | Supabase Postgres, 서울 리전 | RLS로 DB가 본인 데이터만 읽고 쓰게 막는다. API 서버를 따로 만들지 않는다 |
| 콘텐츠 | 앱 번들 JSON + Supabase Storage의 새 버전 | 앱 업데이트 없이 문제를 추가한다. 못 받으면 번들 콘텐츠를 쓴다 |
| 크래시 리포팅 | Firebase Crashlytics | 무료 |
| 백업 | GitHub Actions로 `pg_dump` 정기 실행 | 무료 플랜의 백업 한계를 보완한다 |

서버는 Supabase 하나로 운영한다. 인증, DB, 콘텐츠 파일(Storage), 관리 작업(Edge Functions)을 모두 Supabase에서 처리하고, 별도 API 서버와 웹 호스팅은 두지 않는다. 예외로 개인정보처리방침과 계정 삭제 요청 페이지는 스토어 요건이라 GitHub Pages 정적 페이지로 둔다.

계정과 동기화:

- 로그인 없이 게스트로 제한 없이 쓴다. 기록 백업이나 기기 간 저장을 원하면 그때 로그인한다(2026-10-25). 처음부터 로그인을 강제하면 앱을 써 보기 전에 이탈한다. 나중에 iOS를 낼 때는 심사 요건이기도 하다.
- 이메일·비밀번호 가입은 넣지 않는다. 비밀번호 재설정과 유출 대응 부담을 피한다.
- 서버에는 풀이 기록(id, 시나리오, 3단계 채점 결과, 풀이 날짜)과 데일리 완료 기록(id, 데일리, 완료 날짜)만 쌓는다. XP, 레벨, 연속 학습일, 복습 일정은 이 두 기록으로 앱에서 계산한다.
- 기록 id는 앱에서 만든 UUID다. 기기 두 대의 기록은 id 기준으로 합치고, 같은 요청이 두 번 와도 한 번만 저장된다.
- 풀이 날짜는 기기 기준 날짜로 저장한다. 서버 시간대 때문에 연속 학습일이 틀어지지 않게 한다.
- 개인정보는 Google 계정의 이름과 이메일만 받는다. 앱 안에서 회원 탈퇴하면 계정과 풀이 기록을 모두 삭제한다.

비용은 Google Play 등록비(1회 $25)만 든다. iOS를 출시할 때 Apple 등록비(연 $99)가 더해진다. Supabase는 무료 플랜으로 시작하고, DB가 400MB를 넘으면 Pro(월 $25)로 올린다. 문제 생성·검토에 쓰는 Claude API는 Claude Max 플랜의 월간 API 크레딧(Max 5x 월 $100)으로 운영하고, 급하지 않은 일괄 작업은 Batch API(50% 할인)로 돌린다. 크레딧은 이월되지 않으므로 콘텐츠 작업을 달마다 나눠 한다.

## 리스크와 다음 단계

가장 큰 리스크는 콘텐츠 작업량과 성인이 매너 앱을 꾸준히 쓸지에 대한 불확실성이다.

| 리스크 | 대응 |
| --- | --- |
| 문제를 100개 이상 직접 써야 한다 | 생성·검토 에이전트가 초안과 1차 검토를 하고, 사람은 표시된 문제만 승인한다 |
| 위치 퀴즈 그림 제작에 시간이 많이 든다 | 길, 식당 테이블, 차량, 엘리베이터 4개 템플릿을 재사용한다 |
| 매너는 상황마다 다를 수 있다 | "가장 무난한 선택" 기준으로 채점하고 해설에 이유를 쓴다 |
| 연애 콘텐츠가 성별 논란에 휘말릴 수 있다 | 성별 중립 표현, 의견이 갈리는 주제 제외 |
| 성인의 장기 사용이 증명되지 않았다 | 포트폴리오가 목적이므로 사용자 수보다 완성도와 설계 판단을 보여준다 |
