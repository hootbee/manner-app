# 고정된 결정

기술 결정의 원본은 이 파일 하나다. 자세한 근거와 스키마는 `docs/adr/`에 있다. 결정이 바뀌면 여기를 먼저 고치고, 다른 문서는 이 파일을 가리키기만 한다.

바꾸자고 제안하려면 구체적인 근거(비용, 심사 거절, 데이터 유실 위험 같은 것)가 있어야 한다. 근거 없이 다시 논의하지 않는다.

- 품질 목표: 둘이 부딪히면 위가 이긴다.
  1. 사용자 모르게 기록을 잃지 않는다(아래 "동기화", ADR 0008 G2 3·4번).
  2. 오프라인에서도 학습이 끊기지 않는다(아래 "인증"과 "콘텐츠", G2 1·2번).
  3. 본인 기록만 읽고 쓰고, 계정에 묶인 개인정보는 최소로 받는다(아래 "데이터 권한"과 "개인정보", RLS·cascade 테스트, `delete-account` 테스트).
  4. 사람이 승인하지 않은 문제는 앱에 나가지 않는다(아래 "AI").
  5. 앱이 죽지 않는다(G3, G4).
- 앱: Flutter로 만든다. 지금은 Android만 출시한다. iOS는 나중에 같은 코드로 낸다.
- 서버: Supabase 하나만 쓴다. Auth, Postgres(서울 리전), Storage, Edge Functions. 별도 API 서버, Vercel, 웹 호스팅은 두지 않는다. 예외로 개인정보처리방침과 계정 삭제 요청 페이지는 GitHub Pages 정적 페이지로 둔다. 삭제 요청 페이지는 정적 안내와 운영 이메일만 둔다. 웹 로그인 삭제 흐름은 앱 밖 삭제 요청이 늘면 넣는다.
- 인증: Google 로그인만 쓴다. 이메일·비밀번호 가입은 없다. Apple 로그인은 iOS를 출시할 때 다시 본다(App Review 4.8). 로그인 없이 게스트로 제한 없이 쓴다. 로그인은 사용자가 기록 백업이나 기기 간 저장을 원할 때 한다. 강제로 권하지 않는다.
- 데이터 권한: 클라이언트가 Postgres에 직접 접근하고, RLS로 본인 데이터만 읽고 쓰게 막는다.
- 동기화: 서버에는 추가 전용 기록 두 가지만 쌓는다. 자세한 스키마는 `docs/adr/0001-attempt-records.md`에 있다.
  - 풀이 기록 `attempts`: id, 시나리오, 3단계 채점 결과 `grade`(`best | ok | avoid`), 기기 기준 풀이 날짜
  - 데일리 완료 기록 `day_completions`: id, 데일리, 기기 기준 완료 날짜
  - 기록 id는 앱에서 만든 UUID다. 기기 간 기록은 id 기준 합집합으로 합친다. XP, 레벨, 연속 학습일, 복습 일정은 이 기록으로 앱에서 계산한다.
- 개인정보: Google 계정의 이름과 이메일만 받는다. 앱 안에서 탈퇴하면 계정과 기록을 모두 지운다.
- 콘텐츠: 앱 번들 JSON이 기본이다. Supabase Storage에 올린 새 버전을 받아 덮어쓴다. 못 받으면 번들을 쓴다.
- 콘텐츠 모델은 세 층이다.
  - 매너: id, 원칙, 장소
  - 시나리오: `vary` 축을 조합해 펼치는 문제 틀
  - 데일리: 매너 id만 참조하는 하루 일과 경로
- 학습 규칙
  - 매너 단위 Leitner 간격 반복(1일, 3일, 7일). 그날 그 매너를 모두 최선으로 풀면 한 칸 오르고(최대 3칸), 아니면 1칸으로 간다.
  - 복습할 매너는 데일리 장면의 둘째 문제 자리에 하루 3개까지 넣는다.
  - 세트 안 다시 풀기는 틀린 같은 문제를 세트 맨 뒤에 다시 낸다. 맞힐 때까지 반복한다.
  - 채점은 최선·괜찮음·피해야 함 3단계. 순서 문제는 모두 맞으면 최선, 하나라도 틀리면 피해야 함이다.
  - XP는 모든 풀이의 점수 합(최선 10, 괜찮음 5, 피해야 함 0). 콤보는 세트 안 연출로만 쓰고 저장하지 않는다.
  - 연속 학습일은 `day_completions`의 완료 날짜로 계산한다.
  - 레벨은 100 XP마다 1 오른다(레벨 = XP ÷ 100 + 1, 나머지가 다음 레벨까지의 진행).
  - 영역 스탯은 영역별 0~100 값이고 육각형으로 보여준다. 그 영역에서 푼 매너들의 칸 수 합 × 5(최대 100)이고, 복습이 밀린 매너는 한 칸 낮게 친다. 은퇴한 매너는 뺀다.
- 트랙
  - 데일리: 하루 3장면, 장면당 2문제(하루 약 6문제와 다시 풀기), 약 3분, 중간 저장 없음. 주간 보상, 하루 돌아보기, 시간 제한 모드는 없다.
  - 카테고리별 연습: XP는 주지만 연속 학습일에는 넣지 않는다. 카테고리 기준은 아직 정하지 않았다.
- AI
  - 앱 실행 중에는 AI를 쓰지 않는다.
  - Claude는 문제 생성·검토 파이프라인에서만 쓴다.
  - 파이프라인은 GitHub Actions에서 돈다. 사람이 PR로 승인하면 결과를 Supabase Storage에 올린다.
  - 비용은 Claude Max 플랜의 월간 API 크레딧으로 감당한다. 급하지 않은 일은 Batch API로 돌린다.
- 운영: 크래시는 Firebase Crashlytics로 받는다. 사용자 행동 분석은 Firebase Analytics로 하고, 이벤트는 최소한으로 둔다(`docs/adr/0006-analytics.md`). 백업은 별도 비공개 리포의 GitHub Actions에서 정기 `pg_dump`로 하고 30일 보관한다.
- 예산: 스토어 등록비 외에는 무료 플랜 안에서 버틴다. Supabase Pro는 DB가 400MB를 넘을 때만 올린다.
